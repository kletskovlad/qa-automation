## Лабораторна робота №6

**Тема:** Основи автоматизації тестування вебінтерфейсу. Локатори, взаємодія з елементами та механізм очікування. Playwright.

**Індивідуальний варіант:** №5 — бічне меню: відкриття, перевірка складу пунктів, вихід із системи через `Logout` із поверненням на сторінку входу.

### Реалізовані функції

- Налаштовано Playwright для автоматизованого тестування вебінтерфейсу.
- Створено окрему конфігурацію `playwright.config.ts` для основного набору E2E-тестів.
- Налаштовано запуск тестів у двох браузерах: Chromium та Firefox.
- Встановлено базову адресу тестового вебзастосунку `https://www.saucedemo.com`.
- Налаштовано використання атрибута `data-test` для пошуку елементів через Test ID.
- Реалізовано допоміжні функції для повторного використання кроків авторизації.
- Використано локатори Playwright для пошуку полів введення, кнопок, посилань та елементів каталогу.
- Застосовано автоматичне очікування Playwright і асинхронні перевірки через `expect`.
- Налаштовано формування HTML-звіту за результатами виконання тестів.
- Додано збереження трасування виконання тестів і скриншотів у разі помилок.

### Проведене тестування

- Реалізовано автоматизовані перевірки авторизації користувачів.
- Перевірено успішний вхід користувача `standard_user`.
- Перевірено обробку помилки для заблокованого користувача `locked_out_user`.
- Перевірено валідацію форми входу під час введення порожнього імені користувача.
- Перевірено наявність шести товарів у каталозі.
- Перевірено сортування товарів за ціною від дешевших до дорожчих.
- Перевірено додавання товару Backpack до кошика та оновлення лічильника.
- Перевірено видалення товару Bike Light із кошика та зникнення лічильника, коли кошик стає порожнім.
- Реалізовано порівняння п'яти способів пошуку поля Username.
- Перевірено локатори за роллю (`getByRole`), плейсхолдером (`getByPlaceholder`), Test ID (`getByTestId`), CSS-селектором і XPath.
- Перевірено виконання основного набору тестів окремо у Chromium та Firefox.

### Індивідуальний варіант №5

- Реалізовано два незалежні тести для перевірки бічного меню.
- Перевірено відкриття бічного меню після натискання кнопки `Open Menu`.
- Перевірено наявність чотирьох очікуваних пунктів меню: `All Items`, `About`, `Logout` і `Reset App State`.
- Перевірено доступність пунктів меню після його відкриття.
- Реалізовано вихід із системи через пункт `Logout`.
- Перевірено повернення користувача на сторінку авторизації.
- Перевірено наявність полів Username і Password та кнопки Login після виходу.
- Обидва сценарії виконуються в Chromium і Firefox.

### Експеримент із механізмами очікування

- Створено окремий набір експериментальних тестів для порівняння різних способів очікування.
- Використано обліковий запис `performance_glitch_user` для перевірки поведінки застосунку за умов уповільненого завантаження.
- Порівняно явну паузу `waitForTimeout(1000)`, автоматичне очікування Playwright та явну паузу `waitForTimeout(5000)`.
- Для кожного способу виконано по 10 повторів у браузері Chromium.
- Зафіксовано кількість успішних, невдалих і пропущених запусків, а також загальний час виконання команди.
- Результати експерименту збережено у форматах Markdown і CSV.

| Спосіб очікування | Успішно | Невдало | Пропущено | Загальний час команди |
|---|---:|---:|---:|---:|
| Явна пауза 1000 мс | 10/10 | 0 | 0 | 68,66 с |
| Автоматичне очікування | 10/10 | 0 | 0 | 64,24 с |
| Явна пауза 5000 мс | 10/10 | 0 | 0 | 93,49 с |

- Усі 30 експериментальних запусків завершилися успішно.
- Найменший загальний час виконання серед трьох перевірених способів показало автоматичне очікування Playwright.
- Явна пауза тривалістю 5000 мс продемонструвала найбільший загальний час виконання.
- Результати підтверджують доцільність використання автоматичного очікування замість зайвих фіксованих затримок у звичайних E2E-тестах.

### Діагностика та саморецензування

- Створено окрему конфігурацію `playwright.diagnostic.config.ts` для діагностичних тестів.
- Додано окремий тест із навмисно неправильним очікуванням кількості товарів у каталозі для відтворення помилки.
- Передбачено використання Playwright UI Mode і Debug Mode для покрокового аналізу виконання тестів.
- Передбачено аналіз трасування через Trace Viewer, зокрема знімків сторінки, мережевих запитів і повідомлень консолі.
- Діагностичні тести відокремлено від основного набору успішних E2E-перевірок.
- Проведено самоперевірку структури проєкту, конфігурацій, локаторів, очікувань і розподілу тестів за призначенням.
- Перевірено, що експериментальні та діагностичні сценарії не змішуються з основним набором тестів.

### Результати

- Успішно пройдено **20 із 20 основних автоматизованих E2E-тестів**.
- Перевірки виконано у двох браузерах: Chromium та Firefox.
- Основний набір містить сценарії авторизації, перевірки каталогу, порівняння локаторів і роботи бічного меню.
- Для індивідуального варіанта №5 успішно виконано **4 із 4 запусків** двох тестових сценаріїв у двох браузерах.
- Усі п'ять способів пошуку поля Username успішно перевірено.
- В експерименті з очікуваннями виконано **30 із 30 успішних запусків** у Chromium.
- Для експерименту сформовано підсумкові файли Markdown і CSV.
- Підготовлено окремі конфігурації та тест для діагностики помилок.
- Налаштовано формування HTML-звіту Playwright.

### Встановлення залежностей

npm install

### Встановлення браузерів Playwright

npx playwright install chromium firefox

### Запуск усіх основних E2E-тестів

npm run test:e2e

### Запуск тестів окремо у Chromium

npx playwright test --project=chromium

### Запуск тестів окремо у Firefox

npx playwright test --project=firefox

### Тестування індивідуального варіанта №5

npx playwright test tests/e2e/menu.spec.ts

### Перевірка п'яти локаторів Username

npx playwright test tests/e2e/locators.spec.ts

### Перегляд HTML-звіту

npx playwright show-report

### Запуск генератора коду локаторів

npx playwright codegen https://www.saucedemo.com

### Запуск експериментальних тестів

npx playwright test -c playwright.experiment.config.ts

### Формування підсумків експерименту

npm run test:e2e:experiment:summary

### Запуск діагностичних тестів

npx playwright test -c playwright.diagnostic.config.ts

### Перегляд трасування

npx playwright show-trace шлях-до-trace.zip

### Основні файли лабораторної

- `playwright.config.ts` — основна конфігурація Playwright.
- `playwright.experiment.config.ts` — конфігурація експериментальних тестів.
- `playwright.diagnostic.config.ts` — конфігурація діагностичних тестів.
- `tests/e2e/data.ts` — тестові облікові дані.
- `tests/e2e/helpers.ts` — допоміжні функції для тестів.
- `tests/e2e/login.spec.ts` — перевірки авторизації.
- `tests/e2e/inventory.spec.ts` — перевірки каталогу товарів і кошика.
- `tests/e2e/locators.spec.ts` — порівняння п'яти локаторів Username.
- `tests/e2e/menu.spec.ts` — перевірки індивідуального варіанта №5.
- `tests/experiments/waiting.spec.ts` — експеримент із механізмами очікування.
- `tests/diagnostics/failing-inventory.spec.ts` — тест із навмисно неправильним очікуванням для діагностики.
- `scripts/summarize-waiting-experiment.mjs` — формування підсумків експерименту.
- `docs/lab6/locator-analysis.md` — аналіз локаторів.
- `docs/lab6/waiting-summary.md` — підсумки експерименту з очікуваннями.
- `docs/lab6/REPORT_CHECKLIST.md` — контрольний список для оформлення звіту.
- `results/lab6/waiting-summary.md` — згенерований підсумок експерименту.
- `results/lab6/waiting-summary.csv` — результати експерименту у форматі CSV.

### Висновок

У ході лабораторної роботи досліджено автоматизацію тестування вебінтерфейсу за допомогою Playwright. Реалізовано перевірки авторизації, каталогу товарів, кошика, локаторів і бічного меню. Налаштовано запуск тестів у Chromium та Firefox, автоматичне очікування елементів і формування HTML-звіту.

За індивідуальним варіантом №5 реалізовано перевірку відкриття бічного меню, його складу та виходу із системи через `Logout` із поверненням на сторінку авторизації. Обидва сценарії успішно виконалися в обох браузерах.

Проведений експеримент із механізмами очікування показав, що автоматичне очікування Playwright забезпечило найменший загальний час виконання серед трьох перевірених способів. Додатково підготовлено засоби діагностики помилок і проведено самоперевірку реалізованих тестів.

Основний набір автоматизованих перевірок завершився успішно: **20 із 20 тестів пройдено**. Усі 30 експериментальних запусків також завершилися без помилок.
