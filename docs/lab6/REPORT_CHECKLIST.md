# Лабораторна №6: що потрібно реально виконати та заскриншотити

У цьому архіві **весь код підготовлений**, але результати експериментів та знімки
екрана не вигадані. Їх треба отримати запуском на власному комп'ютері.

## 1. Початковий запуск

- [ ] `npm install` та `npx playwright install chromium firefox`
- [ ] `npm test`: попередні тести Vitest (зафіксувати фактичну кількість)
- [ ] `npm run test:e2e`: 9 сценаріїв × 2 браузери = 18 запусків (якщо немає збоїв)
- [ ] `npm run test:e2e:menu`: 2 сценарії × 2 браузери = 4 запуски
- [ ] Знімок термінала з успішним прогоном
- [ ] `npm run test:e2e:report`, знімок HTML-звіту

## 2. Аналіз локаторів (методичка, крок 2)

- [ ] Відкрити `docs/lab6/locator-analysis.md` та перевірити п'ять локаторів
- [ ] `npx playwright codegen https://www.saucedemo.com`
- [ ] Записати, що може зламати кожен локатор; за потреби оновити таблицю

## 3. Експеримент очікування (методичка, крок 6)

Виконати **окремо**, з паузою лише в експериментальному коді:

```powershell
npm run test:e2e:wait-1000
npm run test:e2e:wait-auto
npm run test:e2e:wait-5000
```

Кожна команда запускає один сценарій **10 разів** у Chromium із `workers=1`.
Невдалі тести за 1 с — можливі та очікувані для порівняння;
але не потрібно підганяти результати під очікування методички.
Кількість збоїв залежить від поточної поведінки стенду та мережі.
Фіксувати **справжній** час кожного прогону з термінала.

| Варіант | Невдалих прогонів із 10 | Загальний час |
|---|---|---|
| Явна пауза 1000 мс | (заповнити) | (заповнити) |
| `await expect(page).toHaveURL(...)` | (заповнити) | (заповнити) |
| Явна пауза 5000 мс | (заповнити) | (заповнити) |

**Що показує експеримент:** фіксована коротка пауза не гарантує виконання
умови, а довга витрачає зайвий час; автоповтор перевіряє умову до виконання
або тайм-ауту. В експерименті `evaluate(button.click)` навмисно не чекає
навігацію як звичайна команда Playwright `locator.click`, щоб порівняння
ізольовано вимірювало механізм очікування.

## 4. Діагностика (методичка, крок 7)

```powershell
npm run test:e2e:diagnostics
npm run test:e2e:report
```

- [ ] Навмисне падіння очікуваного числа товарів (7 замість 6)
- [ ] Trace Viewer → вкладка **Snapshot/DOM**: стан сторінки до твердження
- [ ] Trace Viewer → вкладка **Network**: HTTP-запити і статуси
- [ ] Trace Viewer → вкладка **Console**: повідомлення браузера
- [ ] Пояснення, як кожна вкладка допомагає діагностиці

Щоб знайти trace.zip у PowerShell:

```powershell
$trace = Get-ChildItem .\test-results -Filter trace.zip -Recurse | Select-Object -First 1 -ExpandProperty FullName
npx playwright show-trace "$trace"
```

Додаткові інструменти, які слід продемонструвати:

```powershell
npx playwright test --config=playwright.config.ts --ui
npx playwright test --config=playwright.diagnostic.config.ts --debug
```
