# ЛР №6 — аналіз п'яти локаторів поля Username

Тестовий сайт: https://www.saucedemo.com. Нижче наведено варіанти для дослідження
поля логіна. Під час захисту перевірте їх у DevTools та `npx playwright codegen`.

| Спосіб | Приклад | Що може зламати | Стійкість |
|---|---|---|---|
| За роллю | `page.getByRole('textbox', { name: 'Username' })` | Вилучення/зміна доступної назви поля (accessible name), роль змінюється | Висока за коректної доступності |
| За підказкою | `page.getByPlaceholder('Username')` | Зміна placeholder / локалізація | Висока, але прив'язана до тексту |
| За тестовим атрибутом | `page.getByTestId('username')` (`testIdAttribute: 'data-test'`) | Видалення або перейменування `data-test="username"` | Дуже висока, якщо атрибут стабільний |
| CSS-селектор | `page.locator('#user-name')` | Зміна `id="user-name"` | Середня/висока; ID не є оформленням |
| XPath з позицією | `page.locator('(//input[@type="text"])[1]')` | Додавання ранішого текстового поля, зміна типу/структури | Низька |

**Примітка:** роль `textbox` із назвою `Username` залежить від того, чи має поле
достатню доступну назву у поточній версії сайту. Якщо селектор не знаходить поля,
це важливий результат аудиту доступності, а не привід без пояснення замінити його
крихким CSS або XPath. Надійний практичний варіант у тестах — `getByPlaceholder`.

**Порівняння в коді каталогу:** позиційний `.nth(2)` залежить від сортування;
`locator('.inventory_item').filter({ hasText: 'Sauce Labs Backpack' })`
знаходить товар за змістом, тому не залежить від його позиції.

**У варіанті №5** відкриття меню визначається роллю і назвою кнопки
`getByRole('button', { name: 'Open Menu' })`; пункти — через
`getByRole('link', { name: 'Logout' })` тощо. Відповідно тести не залежать від
`bm-*` класів оформлення меню. Результат виходу перевіряється появою форми входу.
